- Work in phases. After each phase, STOP, summarize what was built, list anything unverified or untested, and wait for my confirmation.

## 1. Stack
Next.js 14+ (App Router), TypeScript (strict), Tailwind CSS, Framer Motion + GSAP ScrollTrigger (hero), MongoDB (Mongoose), Zod (validation), Upstash Redis or in-memory LRU (rate limiting/cache), deploy on Vercel.

## 2. Design direction
- LIGHT theme only. Warm off-white base, festival-style expressive typography, generous whitespace, soft shadows.
- Each society has an accent colour; the page background wash transitions to it as the hero scrolls.
- Smooth, but respect prefers-reduced-motion. Mobile-first. Target Lighthouse 90+.

## 4. Landing hero (reference: https://a24.raviklaassens.com/ — take the interaction idea only, never copy its code or assets)
- A pinned (sticky) section driven by scroll PROGRESS (GSAP ScrollTrigger or Framer useScroll). Do NOT hijack wheel/touch events.
- One object per society, rotating/revolving into the front as the user scrolls; an info panel (name, tagline, "Explore" link) changes in sync; side index lists all societies and is clickable.
- Objects (use ONE consistent style: pre-rendered transparent WebP/AVIF with soft shadow; leave a SocietyObject interface so live 3D (react-three-fiber + Draco GLB) can replace images later):
  - AMS: photography, camera
  - Geneticx: dance, disco ball
  - Sarasva: literary, rolled letter that unrolls when it reaches the front (text must be real HTML, not part of the image)
  - Nirmiti: art, paintbrush
  - Rangtarangini: stage/drama, clapboard
  - Virtousi: music, vinyl disc
- Society list and objects come from MongoDB (not hard-coded). Must work with N societies, not exactly 6.
- Mobile: simpler vertical layout, lazy-load images, static poster fallback. Audio, if added, is muted by default.
- Below the hero: about the college, cultural activities, fests, next-fest CTA, gallery preview, footer. Add a visible "skip to content" link.

## 5. Flickr wrapper (server-only, read-only)
- API key and user ID only in server env vars (FLICKR_API_KEY, FLICKR_USER_ID). Files in lib/flickr start with `import "server-only"`.
- Only GET routes. Other methods return 405.
- Allowlist of Flickr methods: flickr.photosets.getList, flickr.photosets.getPhotos (add others only if needed). Clients can never choose the method.
- Validate inputs with Zod: album ID format, page >= 1, per_page <= 50.
- Return only trimmed fields (id, title, image URLs for fixed sizes, width, height). Never forward raw Flickr responses or errors; return generic error messages.
- Cache responses (revalidate ~10 min) and rate-limit per IP.
- No OAuth and no write permissions anywhere. Use a key that has no write access.
- Hotlink the final image URLs from Flickr's CDN via next/image with a remotePatterns allowlist (staticflickr.com). Check Flickr's terms of use for the display requirements.

## 6. Security checklist
- Security headers: CSP, X-Content-Type-Options, Referrer-Policy, frame-ancestors none, HSTS.
- Zod validation on all inputs; no raw DB queries from user input.
- Rate limiting on /api/*; env validation at startup.
- Any admin/content-editing area (if added later) needs real auth (NextAuth/Auth.js), role checks, and CSRF protection. NOT part of v1.
- npm audit and lockfile committed; no secrets in the repo (.env.local in .gitignore).
